# 03-projetos/completed

## O que é esta pasta

Esta pasta guarda projetos concluídos.

## Para que ela serve

Esta subpasta ajuda a separar ideias candidatas, projetos ativos e projetos que mudaram de estado ao longo do tempo.

## Quando usar

- Quando o objetivo do projeto foi alcançado.
- Quando os outputs finais foram gerados.
- Quando ainda vale preservar decisões, contexto e aprendizados.

## Quando não usar

- Não use para criar projetos fictícios.
- Não use para notas soltas sem intenção clara de projeto; nesse caso use `00-inbox/` ou `02-areas/03-projetos-ideas/`.
- Não use para guardar outputs finais; eles pertencem a `05-saidas/`.

## O que colocar aqui

- Contexto do projeto ou da ideia, quando existir.
- Tarefas, decisões, riscos e próximos passos.
- Links para fontes, domínios, wiki e outputs relacionados.
- Registros de mudança de estado do projeto.

## Exemplos de uso

- Exemplo conceitual: um projeto encerrado com material final.
- Exemplo conceitual: uma entrega concluída que deve ficar consultável.
- Exemplo conceitual: um projeto finalizado que gerou aprendizados.

## Como esta pasta se conecta com o resto do sistema

Projetos podem nascer de `00-inbox/`, amadurecer em `02-areas/03-projetos-ideas/`, virar candidatos em `03-projetos/inbox/`, receber conhecimento de `90-sistema/llm-wiki/wiki/` e gerar materiais finais em `05-saidas/`.

## Fluxo recomendado

1. Registre a ideia ou projeto no estado correto.
2. Se houver decisão importante, registre junto do contexto.
3. Conecte com domínio, wiki, fonte ou output quando houver relação real.
4. Mova para outra subpasta apenas quando o estado mudar de verdade.
5. Peça para a IA revisar tarefas, riscos e próximos passos quando necessário.

## Regras importantes

- Projeto ativo exige confirmação do usuário.
- Mudanças de estado devem preservar contexto útil.
- Decisões e tarefas devem nascer de intenção real, não de exemplos.
- Arquivar não é apagar; é retirar da área ativa.

## Resumo rápido

Use `03-projetos/completed/` para projetos concluídos.
